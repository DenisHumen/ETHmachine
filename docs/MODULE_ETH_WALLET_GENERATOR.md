# Генератор EVM-кошельков

`modules/eth/eth_wallet_generator.py` — создание новых BIP39-мнемоник и
выведение из них EVM-адреса и приватного ключа.

**Меню:** `Tools → Генерация кошельков → EVM-кошельки → Обычная генерация`
**Точка входа:** `eth_generate_wallets(num_wallets)`

Количество спрашивается отдельным меню: `1`, `10`, `100`, `1 000`,
`5 000`, `10 000` или «Ввести вручную» (`config/menu_config.py`,
`WALLET_COUNT_OPTIONS`).

---

## Что генерируется

| Параметр | Значение |
|---|---|
| Мнемоника | BIP39, английский словарь (`mnemonic.Mnemonic("english")`) |
| Путь деривации | `m/44'/60'/0'/0/0` (`ETH_DERIVATION_PATH` + `/0`) |
| PBKDF2 | `BIP39_PBKDF2_ROUNDS = 2048`, HMAC-SHA512 |
| Кривая | `SECP256k1` |
| Адрес | keccak256 от несжатого публичного ключа, EIP-55 checksum |

Приватный ключ пишется без префикса `0x`, в hex.

---

## Двухэтапная проверка

После генерации модуль **заново выводит адрес двумя путями** — из
мнемоники и из приватного ключа — и сравнивает с записанным. Расхождение
помечается в колонке `check` строкой `⚠️⚠️⚠️`.

Прогресс показывается двумя полосами: `[GEN]` (генерация) и `[CHK]`
(проверка).

---

## Куда пишутся ключи

| Путь | Назначение |
|---|---|
| `result/wallets/eth_wallets_<ГГГГММДД_ЧЧММСС>.csv` | файл этого запуска, его больше никто не трогает |
| `result/result.csv` | копия для совместимости |

Колонки после проверки: `mnemonic, wallet_address, private_key, check`.

> Файл запуска существует именно потому, что `result/result.csv` —
> общий: чекеры балансов и конвертеры открывают его на запись (`mode='w'`)
> и затирают всё содержимое. Потерянную мнемонику восстановить нечем,
> поэтому имя файла запуска содержит таймштамп и никогда не
> перезаписывается: при коллизии добавляется суффикс `_2`, `_3`, …

## Красивые адреса

Отдельный пункт меню `Красивые адреса` — см.
[MODULE_SOL_WALLET_GENERATOR.md](MODULE_SOL_WALLET_GENERATOR.md#красивые-адреса)
для общего описания правил поиска; они одни и те же и живут в
`config/modules/cfg_nice_address.py`.

Реализации две, выбор предлагается меню `Реализация генератора`:

| Вариант | Модуль | Примечание |
|---|---|---|
| Python | `modules/eth/eth_nice_address/python/eth_nice_address.py` | работает всегда |
| Rust | `modules/eth/eth_nice_address/eth_nice_address_rust_wrapper.py` | требует Cargo, при его отсутствии меню молча переключается на Python |

Rust-обёртка компилирует бинарник (`cargo build --release` в
`modules/eth/eth_nice_address/rust/`) и запускает его с абсолютными
путями: конфиг — `config/modules/cfg_nice_address.py`, ключи — в
`result/wallets/eth_nice_wallets_<таймштамп>.csv`, копия — в
`result/result.csv`. Для Rust дополнительно спрашивается число потоков
(`0` — все доступные).

Поиск красивого адреса может идти часами. При `Ctrl+C` найденное до
обрыва остаётся в файле запуска.

---

## Безопасность

- Ключи пишутся в открытом виде. `result/` исключён из git, но резервные
  копии и синхронизация на SFTP его включают — см.
  [MODULE_AUTO_BACKUP.md](MODULE_AUTO_BACKUP.md).
- Чтобы использовать сгенерированные кошельки в остальных модулях,
  перенесите нужные строки в `data/data.csv` (колонки `private_key`,
  `wallet_address`, `mnemonic`). Автоматического импорта нет.
