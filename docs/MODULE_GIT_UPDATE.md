# Проверка обновлений и автообновление

`modules/GitHub/check_version.py` — сравнение локального коммита с
`main` в GitHub и обновление с сохранением ваших настроек.

**Точка входа:** `check_version(repo_name)`
`main.py` вызывает `check_version("ETHmachine")` при каждом запуске —
после подготовки окружения и до создания бэкапа.

---

## Как определяется версия

| Что | Откуда |
|---|---|
| Локальный коммит | `git rev-parse HEAD` |
| Коммиты в репозитории | `https://api.github.com/repos/DenisHumen/<repo_name>/commits` |
| Показываемая «версия» | дата коммита в формате `М.ДД.ГГ` |
| Строка `Local version` | файл `db/version`, если он есть |

Коммиты забираются постранично по 100 штук. Локальный коммит ищется в
этом списке; всё, что лежит выше него, считается непринятыми
обновлениями. Если локального коммита в списке нет (форк, своя ветка),
все полученные коммиты попадут в таблицу обновлений.

Таймаут (10 секунд), ошибка сети или пустой ответ — печатается
`Unable to check version`, и программа продолжает запуск: недоступный
GitHub не должен мешать работать.

`db/version` — единственный файл в `db/`, который не исключён из git
(`.gitignore`: `db/*`, `!db/version`).

---

## Что видит пользователь

Если обновлений нет:

```
✅ You are using the latest version!
📅 Last update: <дата последнего коммита>
```

Если есть — таблица `Version | Release Date | Changes` с текстами
коммитов (многострочные сообщения разбиваются по строкам), а под ней
вопрос:

```
🛠️ Do you want to update?
  ⚠️ No, continue without updating
  🆙 Yes, update to the latest version
```

Ответ «No» — программа просто идёт дальше.

## Обновление

`run_update()` выполняет по шагам:

1. `git status --porcelain` — есть ли локальные изменения.
2. Если есть — предупреждение и второй вопрос: «отложить изменения,
   обновиться и вернуть их» или «отменить обновление».
3. `git stash push --include-untracked -m "ETHmachine auto stash <дата>"`.
4. `git pull`.
5. `git stash pop` — возврат ваших правок.
6. Перезапуск: `subprocess.run([sys.executable, main.py])`, затем
   `sys.exit(0)`.

Все git-команды выполняются с `cwd`, равным корню репозитория.

### Почему обязательно stash

Настройки лежат в **отслеживаемых** файлах `config/**`. Без stash
`git pull` упирается в локальные изменения и отказывается работать.

Раньше stash делался, но никогда не возвращался: после обновления
настройки пользователя оказывались сброшены к значениям из репозитория,
а его правки — забыты в stash. Теперь шаг 5 обязателен, и без него
перезапуска не происходит.

`--include-untracked` захватывает и новые файлы, но **не игнорируемые**:
`data/`, `db/`, `result/`, `log/`, `backups/` и
`config/cex_settings.py` перечислены в `.gitignore`, поэтому в stash не
попадают и обновлением не затрагиваются.

### Если что-то пошло не так

| Ситуация | Поведение |
|---|---|
| `git pull` упал | изменения возвращаются из stash, репозиторий остаётся прежним, перезапуска нет |
| `git stash pop` дал конфликт | печатается вывод git и подсказка: открыть перечисленные файлы, оставить нужные значения, убрать маркеры `<<<<<<<` / `=======` / `>>>>>>>`; **перезапуска не происходит** |
| Не удалось отложить изменения | обновление отменяется, файлы не трогаются |

Ваши правки в любом случае не теряются — они лежат в stash. Посмотреть:

```bash
git stash list
git stash pop
```

Перезапуска нет намеренно: работать с настройками, застрявшими в
конфликте, хуже, чем остановиться и разобраться.

## Обновление вручную

```bash
git pull
pip install -r requirements.txt
```

Формат `data/data.csv`, пути баз в `db/` и имена настроек между версиями
не меняются — перенастраивать после обновления ничего не нужно.
