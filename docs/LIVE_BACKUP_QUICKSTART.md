# Live-бэкап: быстрый старт

Пять шагов, чтобы `data/`, `db/` и `result/` автоматически уезжали на ваш
SFTP-сервер зашифрованным архивом.

Полное описание — [MODULE_LIVE_BACKUP_SYNC.md](MODULE_LIVE_BACKUP_SYNC.md).
Обычные копии и ротация — [MODULE_AUTO_BACKUP.md](MODULE_AUTO_BACKUP.md).

---

## 1. Поставьте paramiko

```bash
pip install paramiko
```

Без него SFTP-часть отключается, и в логе появляется предупреждение.

## 2. Заполните конфиг

`config/modules/cfg_backup.py`:

```python
SFTP_SERVER_INTO_BACKUP_ENABLE = True
SFTP_LIVE_SYNC_ENABLE = True

SFTP_SERVER_INTO_BACKUP = {
    'host': 'sftp.example.com',
    'port': 22,
    'username': 'user',
    'password': 'secret',          # или оставьте пустым и укажите key_file
    'key_file': '',                # путь к SSH-ключу, приоритетнее пароля
    'remote_path': 'backups/',
    'identificator': 'home-pc',    # своя метка на каждой машине
    'password_encryption': 'длинный-пароль-шифрования',
}
```

**`password_encryption` лучше задать здесь.** Иначе программа спросит его
в терминале — а фоновый мониторинг вводить пароль некому.

**`identificator` должен быть разным на разных машинах.** Он входит в имя
файла на сервере; при совпадении машины затрут копии друг друга.

## 3. Проверьте связь

Запустите `python main.py`, зайдите в `Backup → Проверить связь с SFTP`.
Должно быть «Подключение успешно».

## 4. Создайте первую копию

`Backup → Обновить live-копию`. На сервере появится
`live_backup_<identificator>.zip.encrypted`.

## 5. Готово

Дальше при каждом запуске программы поднимается фоновый поток: раз в
60 секунд он сверяет хэши файлов и, если что-то изменилось, обновляет
копию на сервере. На сервере всегда лежит одна актуальная версия.

Проверить состояние — `Backup → Состояние live-копии`.

---

## Восстановление на другой машине

1. Клонируйте репозиторий и поставьте зависимости.
2. Пропишите те же `SFTP_SERVER_INTO_BACKUP` и **тот же**
   `identificator`.
3. `python main.py` → `Backup` → `Восстановить из live-копии`.
4. Введите пароль шифрования, если он не задан в конфиге.

> Восстановление перезаписывает текущие `data/`, `db/` и `result/`.
> Меню спросит подтверждение, ответ по умолчанию — «нет».

## Частые вопросы

**Что попадает в копию?** Каталоги из `DIRECTORIES_TO_BACKUP` — по
умолчанию `data`, `db`, `result`. Настройки `config/` в архив не входят.

**Забыл пароль шифрования.** Расшифровать нечем. Пароль нигде не
хранится и не восстанавливается.

**Можно без шифрования?** Оставьте `password_encryption` пустым и не
вводите пароль в терминале — копия уедет открытой. В ней приватные ключи,
так что делайте так только на сервере, который полностью ваш.

**Мешает ли live-режим обычным копиям?** Нет, это независимые механизмы:
обычные копии лежат в `backups/` и ротируются по
`MAX_BACKUPS_TO_KEEP`, live-копия существует на сервере в одном
экземпляре.
