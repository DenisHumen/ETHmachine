# Live-синхронизация на SFTP

Режим, в котором программа сама следит за изменениями `data/`, `db/` и
`result/` и держит на SFTP-сервере **одну актуальную зашифрованную
копию**. Реализация — `LiveSyncMonitor` и методы `create_live_backup` /
`restore_live_backup` в `modules/backup/backup_manager.py`.

Если нужно просто включить и пользоваться — см.
[LIVE_BACKUP_QUICKSTART.md](LIVE_BACKUP_QUICKSTART.md).
Про обычные копии и SFTP-выгрузку — [MODULE_AUTO_BACKUP.md](MODULE_AUTO_BACKUP.md).

---

## Чем отличается от обычного бэкапа

| | Обычный бэкап | Live-копия |
|---|---|---|
| Когда создаётся | по команде и при старте программы | автоматически, при изменении файлов |
| Сколько версий на сервере | до `MAX_BACKUPS_TO_KEEP` | ровно одна |
| Имя файла | `backup_<таймштамп>.zip` | `live_backup_<identificator>.zip.encrypted` |
| Шифрование | нет | да, Fernet + PBKDF2 |
| Локальная копия | остаётся в `backups/` | временный файл удаляется после выгрузки |

Live-копия отвечает на вопрос «что у меня сейчас», а не «что было
вчера». Историю по-прежнему даёт ротация обычных копий.

## Включение

```python
# config/modules/cfg_backup.py
SFTP_SERVER_INTO_BACKUP_ENABLE = True   # live работает только поверх SFTP
SFTP_LIVE_SYNC_ENABLE = True

SFTP_SERVER_INTO_BACKUP = {
    'host': 'sftp.example.com',
    'port': 22,
    'username': 'user',
    'password': 'secret',        # либо key_file
    'key_file': '',              # приоритетнее пароля
    'remote_path': 'backups/',
    'identificator': 'home-pc',  # метка машины
    'password_encryption': '',   # пусто — спросим в терминале
}
```

То же самое переключается из меню `Backup → Live-синхронизация`: оно
переписывает флаг прямо в `config/modules/cfg_backup.py`, поэтому
настройка переживает перезапуск.

### `identificator`

Входит в имя файла: `live_backup_<identificator>.zip.encrypted`. Если
поле пустое, подставляется `main`.

Разные машины с **одинаковым** `identificator` будут перезаписывать
копию друг друга. Задавайте разные метки: `home-pc`, `vps-1`, `laptop`.

## Как работает мониторинг

`main.py` при старте, если включены оба флага, создаёт `BackupManager` и
вызывает `start_live_monitoring()` — поток-демон. При выходе из главного
меню поток останавливается.

Цикл `LiveSyncMonitor.monitor_loop`:

1. Если на сервере ещё нет live-копии — создаёт начальную.
2. Спит `check_interval` — **60 секунд**.
3. Считает хэши файлов в `DIRECTORIES_TO_BACKUP` и сравнивает с
   предыдущим снимком.
4. Изменения есть → собирает архив, шифрует, удаляет старую копию с
   сервера, заливает новую.

Изменением считается любое отличие набора файлов и их содержимого.
Проверка идёт по хэшам, а не по времени модификации: так копия не
пересоздаётся из-за файла, который просто открыли на запись.

Интервал 60 секунд задан в коде (`self.check_interval = 60`) и в конфиг
не вынесен.

## Шифрование

| Что | Как |
|---|---|
| Алгоритм | Fernet |
| Ключ | PBKDF2-HMAC-SHA256, 100 000 итераций, 32 байта |
| Соль | фиксированная, `b'ETHmachine_backup_salt_v1'` |

Пароль берётся из `password_encryption`. Если пусто — запрашивается в
терминале (с подтверждением) и кэшируется на сессию. Для фонового
мониторинга это означает, что пароль лучше задать в конфиге: иначе
первый же цикл упрётся в приглашение ввода.

Пустой пароль — копия уедет **незашифрованной**, о чём будет
предупреждение.

Соль одинакова на всех машинах намеренно: только так копию, снятую на
одном компьютере, можно развернуть на другом, зная лишь пароль. Пароль
поэтому должен быть длинным.

## Восстановление

`Backup → Восстановить из live-копии`:

1. Проверка, что копия есть на сервере.
2. Скачивание с прогресс-баром во временный файл в `backups/`.
3. Если имя оканчивается на `.encrypted` — запрос пароля и расшифровка.
   Неверный пароль даёт ошибку дешифрования, временный файл удаляется.
4. Распаковка поверх корня проекта — файл за файлом, с созданием
   недостающих каталогов.
5. Временный файл удаляется.

**Восстановление перезаписывает текущие `data/`, `db/`, `result/`.**
Меню требует явного подтверждения, по умолчанию — «нет».

Перенос на новую машину: клонировать репозиторий, поставить зависимости,
прописать те же `SFTP_SERVER_INTO_BACKUP` и `identificator`, запустить и
выбрать восстановление из live-копии.

## Остальные пункты меню

| Пункт | Что делает |
|---|---|
| Обновить live-копию | снять и залить копию прямо сейчас, не дожидаясь цикла |
| Состояние live-копии | имя файла, `identificator`, есть ли копия на сервере, откуда берётся пароль |
| Удалить live-копию с сервера | удаляет только удалённый файл, локальные копии остаются |

## Если что-то не работает

| Симптом | Причина |
|---|---|
| `Paramiko не установлен` | `pip install paramiko` |
| Меню не показывает live-пункты | `SFTP_SERVER_INTO_BACKUP_ENABLE` или `SFTP_LIVE_SYNC_ENABLE` = `False` |
| `Live бекап не найден на сервере` | копия ещё не создавалась или другой `identificator` |
| `Ошибка дешифрования (неверный пароль?)` | пароль не совпадает с тем, которым шифровали |
| Копия не обновляется | изменений в `data/`, `db/`, `result/` за цикл не было |
