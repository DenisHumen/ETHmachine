# Генератор Solana-кошельков

`modules/sol/sol_wallet_generator.py` — создание BIP39-мнемоник и
выведение из них Solana-адреса и приватного ключа в base58.

**Меню:** `Tools → Генерация кошельков → Solana-кошельки → Обычная генерация`
**Точка входа:** `sol_generate_wallets(num_wallets)`

---

## Что генерируется

| Параметр | Значение |
|---|---|
| Мнемоника | `bip_utils.Bip39MnemonicGenerator` |
| Деривация | BIP44, `Bip44Coins.SOLANA`, account 0, `CHAIN_EXT` |
| Ключ | 64 байта: 32 байта приватного + 32 байта публичного, кодировка base58 |
| Адрес | `solders.keypair.Keypair.pubkey()` |

Формат приватного ключа (base58 от 64 байт) — тот же, что понимают
Phantom и Solflare, и тот же, что ждёт колонка `sol_private_key` в
`data/data.csv`.

---

## Двухэтапная проверка

После генерации адрес выводится заново двумя путями — из мнемоники и из
base58-ключа — и сравнивается с записанным. Расхождение помечается в
колонке `check` строкой `⚠️⚠️⚠️`. Прогресс идёт двумя полосами: `[GEN]` и
`[CHK]`.

---

## Куда пишутся ключи

| Путь | Назначение |
|---|---|
| `result/wallets/sol_wallets_<ГГГГММДД_ЧЧММСС>.csv` | файл этого запуска |
| `result/result.csv` | копия для совместимости |

Колонки: `mnemonic, wallet_address, private_key, check`.

> `result/result.csv` открывают на запись чекеры балансов и конвертеры —
> содержимое затирается. Файл запуска с таймштампом не перезаписывается
> никогда: при совпадении имён добавляется суффикс `_2`, `_3`, …

## Красивые адреса

**Меню:** `Tools → Генерация кошельков → Solana-кошельки → Красивые адреса`
**Модуль:** `modules/sol/sol_nice_address.py`,
точка входа `sol_generate_nice_wallets(num_wallets)`

Генерация идёт в цикле, пока адрес не пройдёт проверку `is_nice_address`.
Правила берутся из `config/modules/cfg_nice_address.py`:

| Параметр | Значение по умолчанию | Что делает |
|---|---|---|
| `NICE_ADDRESS_WORDS_enable` | `False` | включает поиск по списку слов |
| `NICE_ADDRESS_WORDS_SOL` | 30 строк по 10 одинаковых символов (`AAAAAAAAAA`, `BBBBBBBBBB`, …) | что искать в адресе |
| `REPEATED_CHAR_COUNT_enable` | `True` | включает поиск по повторам |
| `REPEATED_CHAR_COUNT` | `10` | сколько одинаковых символов подряд считать «красивым» |
| `display_the_address_search_process` | `True` | печатать каждый проверенный адрес |

Оба правила независимы: если включены оба, подойдёт адрес, удовлетворяющий
любому из них. Сравнение идёт по адресу, приведённому к нижнему регистру,
поэтому регистр в `NICE_ADDRESS_WORDS_SOL` роли не играет.

Для EVM действует тот же файл настроек, но список слов свой —
`NICE_ADDRESS_WORDS_ETH`, и повторы ищутся только среди hex-символов
`[a-f0-9]`. Подробности — в
[MODULE_ETH_WALLET_GENERATOR.md](MODULE_ETH_WALLET_GENERATOR.md#красивые-адреса).

> `REPEATED_CHAR_COUNT = 10` — это очень редкое событие. Начните с 5–6,
> чтобы понять порядок времени поиска на своей машине. Rust-реализация
> есть только для EVM; Solana ищет на Python.

Результат: `result/wallets/sol_nice_wallets_<таймштамп>.csv` и копия в
`result/result.csv`.

---

## Безопасность

Ключи пишутся в открытом виде. Чтобы использовать кошельки в остальных
модулях, перенесите строки в `data/data.csv` (колонки `sol_address`,
`sol_private_key`) — автоматического импорта нет.
