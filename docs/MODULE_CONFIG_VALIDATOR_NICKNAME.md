# Проверка конфигурации при запуске

`modules/config_validator.py` — валидатор, который `main.py` запускает
после бэкапа и до главного меню (`validate_configuration()`).

Результат делится на две категории:

| Категория | Что происходит |
|---|---|
| **Ошибки** (`errors`) | `validate_configuration()` возвращает `False`, `main.py` печатает панель «В конфигурации есть ошибки» и завершает работу |
| **Предупреждения** (`warnings`) | печатаются, запуск продолжается |

---

## Что проверяется

`validate_all()` вызывает три проверки.

### 1. Файлы конфигурации

Наличие `config/cex_settings.py`. Отсутствие — **ошибка**. Файл создаётся
автоматически при первом запуске (`modules/bootstrap.py`), так что
увидеть эту ошибку можно только если файл удалили вручную.

### 2. Ключи бирж

Импортируются `OKX_ACCOUNTS`, `BINANCE_ACCOUNTS`, `BITGET_ACCOUNTS`,
`MEXC_ACCOUNTS` из `config/cex_settings.py`. Аккаунт считается активным
при `enabled=True` и непустом `api_key`; у активных проверяется набор
обязательных полей:

| Биржа | Обязательные поля |
|---|---|
| OKX | `name`, `api_key`, `api_secret`, `passphrase` |
| Bitget | `name`, `api_key`, `api_secret`, `passphrase` |
| Binance | `name`, `api_key`, `api_secret` |
| MEXC | `name`, `api_key`, `api_secret` |

Пустое поле у активного аккаунта — предупреждение. Полное отсутствие
активных аккаунтов — тоже предупреждение: биржами пользуются не все.
Ошибка импорта самого файла — **ошибка**.

### 3. `data/data.csv`

Файла нет — предупреждение (создастся при первом запуске). Если есть,
построчно проверяются заполненные поля:

| Поле | Правило |
|---|---|
| `private_key` | 64 hex-символа, префикс `0x` необязателен |
| `wallet_address` | `^0x[a-fA-F0-9]{40}$` |
| `evm_cex_address` | то же правило, что и `wallet_address` |
| `proxy`, `reserve_proxy` | `login:password@host:port`; схема (`http://`, `socks5://`) необязательна, host может быть IP или доменом |
| `email` | обычная проверка формата адреса |
| `mnemonic` | ровно 12 или 24 слова |
| `transfer_amount` | `0.1-0.2`, `1-2%`, `10-20token`, `1-2eth`, либо одиночные `5`, `5%`, `5token` |

Дополнительно: если `transfer_amount` заполнен, но пуст `private_key`
или `evm_cex_address`, выдаётся предупреждение — без них модули перевода
не смогут выполнить строку.

Отдельно сверяется набор заголовков. Ожидаются `private_key`, `proxy`,
`reserve_proxy`, `wallet_address`, `mnemonic`, `sol_address`,
`discord_token`, `email`, `email_password`, `email_imap`; недостающие
перечисляются в предупреждении. Полный список колонок — `HEADERS` в
`modules/data_manager.py`, недостающие дописываются автоматической
миграцией.

Все нарушения — предупреждения, а не ошибки: пустая или частично
заполненная строка встречается в реальной работе постоянно.

## Правила для `NICKNAME_GENERATOR`

В валидаторе есть отдельный набор правил для словаря `NICKNAME_GENERATOR`
из `config/modules/cfg_generators.py` (метод
`_validate_nickname_generator`):

| Ключ | Ошибка | Предупреждение |
|---|---|---|
| `MIN_LENGTH` | пусто, не `int`, `< 1`, больше `MAX_LENGTH` | `< 3` или `> 20` |
| `MAX_LENGTH` | пусто, не `int`, `< 1` | `> 50`; разброс `MAX - MIN > 30` |
| `USE_SPECIAL_CHARS` | пусто, не `bool` | — |
| `QUANTITY` | пусто, не `int`, `< 1` | `> 100000` |
| `USE_NUMBERS` | не `bool` | — |
| `MIN_NUMBERS` | не `int`, `< 0`, больше `MAX_NUMBERS` | `> 5` |
| `MAX_NUMBERS` | не `int`, `< 0` | `> 10` |
| `NICE_NUMBERS` | не список; элемент не `int` или `< 0` | элемент `> 99999` |

Проверки `MIN_NUMBERS` / `MAX_NUMBERS` выполняются только при
`USE_NUMBERS = True`.

Рядом лежит `_validate_sftp_config` — проверка `SFTP_SERVER_INTO_BACKUP`
из `config/modules/cfg_backup.py`: непустые `host`, `username`,
`remote_path`, `port` в диапазоне 1–65535, наличие хотя бы одного из
`password` / `key_file` и существование файла ключа на диске.

> **Известное ограничение.** Оба набора правил вызываются из метода
> `_validate_config_py`, а сам этот метод из `validate_all()` не
> вызывается. То есть при запуске программы настройки генератора
> никнеймов и SFTP фактически не проверяются — как и `TYPE_WITHDRAW`,
> `VALUES_TO_WITHDRAW`, `NUM_THREADS`, которые проверяются там же.
> Ошибки в этих параметрах вы увидите не при старте, а при запуске
> соответствующего модуля.

## Запуск отдельно

```bash
python -m modules.config_validator
```

Код возврата: `0` — критических ошибок нет, `1` — есть.
