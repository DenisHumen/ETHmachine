# Вывод средств с OKX

`modules/cex/okx/okx_withdraw.py` — массовый вывод одного токена с OKX на
список адресов из `data/data.csv`.

**Меню:** `CEX → OKX → Вывод средств`
**Точка входа:** `okx_withdraw()`

---

## Что нужно заполнить

| Что | Где |
|---|---|
| API-ключ, секрет, passphrase | `config/cex_settings.py`, список `OKX_ACCOUNTS` |
| Адреса-получатели | колонка `wallet_address` в `data/data.csv` |
| Правила суммы | `config/modules/cfg_cex.py` |

Адреса читаются через `modules.data_manager.get_wallet_addresses()`.
Отдельного файла со списком кошельков нет.

Несколько аккаунтов OKX настраиваются в том же
`config/cex_settings.py` — см.
[MULTIPLE_EXCHANGE_ACCOUNTS.md](MULTIPLE_EXCHANGE_ACCOUNTS.md).

**Важно:** адреса вывода должны быть в белом списке OKX, а у API-ключа
включено право на вывод и добавлен IP, с которого вы работаете.

---

## Настройки суммы

`config/modules/cfg_cex.py` — общий файл для всех четырёх бирж:

| Параметр | Значение по умолчанию | Что делает |
|---|---|---|
| `TYPE_WITHDRAW` | `0` | `0` — сумма задана в самом токене, `1` — в USDT (пересчитывается по курсу) |
| `VALUES_TO_WITHDRAW` | `[0.00496102, 0.005]` | диапазон `[min, max]`; для каждого кошелька берётся своё случайное значение |
| `WAIT_FOR_BALANCE` | `True` | после вывода ждать поступления на кошелёк |

Сумма считается **для каждого кошелька отдельно**
(`calculate_individual_withdraw_amount`) и округляется до 6 знаков — так
переводы не выглядят одинаковыми.

Если минимум диапазона больше доступного баланса, при интерактивном
подтверждении предлагается вывести весь остаток; в рабочем цикле по
кошелькам — весь остаток используется без вопроса.

Также используется `config/modules/general_config.py`: `NUM_THREADS` —
число потоков, `SLEEP_BETWEEN_ACTIONS` — паузы между действиями.

---

## Ход работы

1. Выбор аккаунта OKX (`select_okx_account()`). Если активен один —
   выбирается автоматически.
2. Проверка незавершённого прогресса в `db/okx_withdraw_progress.db`:
   `Продолжить`, `Очистить и начать заново` или `Отменить`.
3. Запрос балансов аккаунта, выбор токена из списка тех, где баланс
   положительный.
4. Запрос доступных сетей для токена (`/api/v5/asset/currencies`) и выбор
   сети.
5. Подтверждение: сумма, сеть, количество кошельков.
6. Пул потоков выводит на каждый адрес: считает индивидуальную сумму,
   получает комиссию сети, отправляет запрос на вывод.
7. При `WAIT_FOR_BALANCE = True` — ожидание поступления на адрес,
   таймаут **1 час** на кошелёк. Не дождались — статус `balance_timeout`.

### Торговый и финансовый счёт

Запросы подписываются HMAC-SHA256 (`OK-ACCESS-SIGN`). Перед выводом, если
`OKX_EU_TYPE = 0` в `config/cex_settings.py`, модуль переводит остаток
токена с торгового счёта на финансовый — вывод возможен только с
финансового. Поставьте `OKX_EU_TYPE = 1`, если у вас депозиты и так
приходят на торговый и перевод не нужен.

---

## Статусы

| Статус | Что означает |
|---|---|
| `pending` | запись создана, кошелёк ещё не обработан |
| `processing` | вывод запущен |
| `success` | вывод принят биржей (и баланс дошёл, если включено ожидание) |
| `failed` | биржа отклонила вывод |
| `balance_timeout` | вывод принят, но за час средства не пришли |
| `error` | исключение или нулевой баланс токена на момент обработки |

## Результаты

| Путь | Что внутри |
|---|---|
| `db/okx_withdraw_progress.db` | таблица `withdraw_progress` — состояние по каждому адресу |
| `result/okx_withdraw_results_<ГГГГММДД>.csv` | лог выводов за день |

Колонки CSV: `timestamp, wallet_address, token, chain, amount, status,
error_message`. Файл дописывается в течение дня.

Прогресс в БД — то, ради чего модуль переживает обрыв: следующий запуск
предложит продолжить и обработает только те адреса, которые остались в
`pending`.
